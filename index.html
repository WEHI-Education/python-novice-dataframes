What is pandas?

  • The standard Python library for tabular data: rows and columns, like a spreadsheet or an R data.frame.
  • Built on NumPy arrays, so it is fast for numeric work.
  • Reads and writes CSV, Excel, JSON, parquet, SQL…
  • Plots via matplotlib, and integrates with seaborn, scikit-learn, statsmodels…
import pandas as pd

Two objects do almost all the work:

Object Shape R analogue
Series 1-D, labelled named vector
DataFrame 2-D table data.frame / tibble

A DataFrame is a dict of Series that share the same row index.

Every column of a DataFrame is a Series, and every Series prints its dtype (and Name) at the bottom.

The index: labels vs positions

Every pandas object carries an index of row labels. You can select by label or by position, and it pays to be explicit.

weights.loc["bob"]     # by label
np.int64(83)
weights.iloc[1]        # by position (0-based!)
np.int64(83)
weights.loc["alice":"bob"]   # label slices are inclusive
alice    68
bob      83
Name: weight, dtype: int64
weights.iloc[0:2]            # position slices are not
alice    68
bob      83
Name: weight, dtype: int64

pandas for R users

Same ideas, different reflexes

R

df[1, ]                 # first row
new_df <- df            # independent copy
mean(df$a)              # function(object)
df$a                    # a vector

pandas

df.iloc[0]              # 0-based positions
new_df = df.copy()      # `new_df = df` is an alias!
df["a"].mean()          # object.method()
df["a"]                 # a Series, with an index
  • Indexing starts at 0, and label slices are inclusive while position slices are not.
  • Assignment does not copy. new_df = df makes a second name for the same object.
  • Methods, not functions. There is no mean(df); call df.mean().
  • A column is a Series, not a bare vector: it carries an index and a dtype.

Creating and reading data

R

df <- data.frame(a = c(1, 2), b = c(3, 4))
df <- read.csv("file.csv")

dim(df); head(df); summary(df)
colnames(df)

pandas

df = pd.DataFrame({"a": [1, 2], "b": [3, 4]})
df = pd.read_csv("file.csv")

df.shape; df.head(); df.describe()
df.columns

pandas wants a dict of lists ({} of []) where R takes named vector arguments.

Selecting and filtering

R pandas
df[rows, cols] df.loc[rows, cols] (labels) / df.iloc[...] (positions)
df$a, df[["a"]] df["a"], df.a
df[, c("a", "c")], select(df, a, c) df[["a", "c"]]
select(df, a:c) df.loc[:, "a":"c"]
df[df$a > 1, ] df[df["a"] > 1], df.loc[df.a > 1]
subset(df, a <= b), filter(df, a <= b) df.query("a <= b")
s %in% c(2, 4) s.isin([2, 4])
with(df, a + b) df.eval("a + b")
distinct(select(df, a)) df[["a"]].drop_duplicates()
sample_n(df, 10) df.sample(n=10)

query() is the closest thing to dplyr’s filter(); external variables are referenced with @var.

Transforming, sorting and grouping

R (dplyr) pandas
mutate(df, c = a - b) df.assign(c=df["a"] - df["b"])
rename(df, col_one = col1) df.rename(columns={"col1": "col_one"})
arrange(df, col1, col2) df.sort_values(["col1", "col2"])
arrange(df, desc(col1)) df.sort_values("col1", ascending=False)
group_by(df, cat) \|> summarise(m = mean(a)) df.groupby("cat")["a"].mean()
group_by(df, cat) \|> summarise(total = sum(a)) df.groupby("cat")["a"].sum()
aggregate(...), tapply(...) df.groupby([...]).agg(...), df.pivot_table(...)
melt(df, id = c("k")) pd.melt(df, id_vars=["k"])
dcast(df, a ~ b, sum) df.pivot_table(values=..., index="a", columns="b", aggfunc="sum")

Grouping returns the grouping column as the row index of the result.

Pipes and method chaining

R

df |>
  filter(a > 1) |>
  group_by(cat) |>
  summarise(mean_b = mean(b))

pandas

(df
   .query("a > 1")
   .groupby("cat")["b"]
   .mean())
  • The |> pipe becomes a chain of .method() calls. Wrap the chain in ( ) to split it over lines.
  • Most methods return a new object, like dplyr verbs. inplace=True is the exception, not the rule.
  • df.plot() is the quick equivalent of base plot(); seaborn is the closest thing to ggplot2.

Beyond pandas: when the data gets big

Polars

A newer DataFrame library written in Rust.

  • Uses all your CPU cores by default
  • Lazy evaluation optimises whole queries
  • Usually 5-20x faster than pandas
  • Familiar verbs: filter, group_by

Use when data fits (or nearly fits) in RAM and you want speed without changing tools.

DuckDB

An in-process analytical SQL database.

  • SQL over CSV, parquet or DataFrames
  • No server to install or manage
  • Handles data larger than memory

Use when you think in SQL, or need to join many large files.

Dask

Parallel pandas across cores or a cluster.

  • Splits a big table into many pandas DataFrames
  • Same API, then call .compute()
  • Scales out to HPC and cloud clusters

Use when you already have pandas code and the data will not fit on one machine.

All three hand results back to pandas (.to_pandas(), .df(), .compute()), so they slot into an existing workflow.
